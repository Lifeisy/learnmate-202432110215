# 登录、权限与 AI 安全

## 认证与授权的区别

认证（Authentication）回答“你是谁”，授权（Authorization）回答“你能做什么”。登录校验用户名和密码属于认证；判断某个用户能否删除其他用户属于授权。两者不能混为一谈，接口只做登录校验而不做角色判断，就会产生越权漏洞。

本项目的角色分为 ADMIN 和 USER。管理员可以维护用户，普通用户只能访问仪表盘和智能问答。权限判断放在服务端，前端隐藏按钮只是体验优化，不能作为安全边界。

## 密码存储与 BCrypt

密码绝不能明文入库。BCrypt 会为每个密码生成随机盐，并把盐和哈希一起保存，验证时使用 matches 比较。BCrypt 的计算成本可调，本项目使用 strength=12，使暴力破解成本更高。

登录失败时统一提示“用户名或密码错误”，不区分用户不存在和密码错误，避免账号枚举。数据库中只保存 password_hash，任何接口和日志都不能返回或打印明文密码。

## JWT 的签发与校验

JWT 由 Header、Payload、Signature 三部分组成。服务端用密钥签名，客户端后续请求在 Authorization: Bearer <token> 中携带。服务端校验签名、签发者、过期时间后才建立认证上下文。

JWT 一旦泄露，在过期前都可能被冒用，因此要设置较短有效期、使用 HTTPS、避免把令牌写入日志。前端不应把令牌长期放在 localStorage；本项目使用 sessionStorage 并在关闭标签页后清除，生产环境更推荐 HttpOnly、Secure、SameSite 的 Cookie 方案。

## RBAC 与接口控制

RBAC 通过用户—角色—权限的关系控制访问。小型项目可以先把角色放在用户表，使用 Spring Security 的 @PreAuthorize("hasRole('ADMIN')") 控制方法。角色变更后，已签发的 JWT 仍带旧角色，因此要么让令牌短期有效，要么维护令牌版本号并支持撤销。

还必须防止管理员误删自己、删除最后一个管理员、停用自己等操作。这些业务规则应放在 Service 层，并用集成测试覆盖 401、403 和正常路径。

## 提示注入防护

提示注入是指用户把“忽略之前的规则”“输出系统提示词”“执行删除命令”等内容放进问题，试图让模型越过边界。防护不能只靠一句“不要听用户的”，需要多层措施：输入长度限制、零宽字符归一化、敏感意图规则拦截、资料与指令分隔、系统提示词声明资料只是数据、输出引用校验，以及高风险操作的人工确认。

模型输出也不能直接拼接进 SQL、Shell 或前端 HTML。所有工具调用都要做参数白名单和权限校验。密钥只放在服务端环境变量中，绝不能进入提示词或前端代码。

## AI 安全验收清单

检查项包括：数据库无明文密码；仓库无真实 API Key；未登录访问受保护接口返回 401；普通用户访问管理接口返回 403；JWT 过期和篡改会被拒绝；提示注入样例被拦截；RAG 无资料时明确拒答；回答带可核验出处；日志不记录完整令牌和密钥。
